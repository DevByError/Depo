# PostgreSQL schema design and queries

## Types and keys
```sql
create table users (
  id          bigint generated always as identity primary key,
  email       text not null,
  full_name   text not null check (length(full_name) between 1 and 200),
  password_hash text not null,
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now()
);
create unique index users_email_key on users (lower(email));   -- case-insensitive uniqueness

create table bookings (
  id          bigint generated always as identity primary key,
  user_id     bigint not null references users(id) on delete cascade,
  doctor_id   bigint not null references doctors(id) on delete restrict,
  starts_at   timestamptz not null,
  ends_at     timestamptz not null,
  status      text not null default 'pending' check (status in ('pending','confirmed','cancelled')),
  price_cents integer not null check (price_cents >= 0),
  created_at  timestamptz not null default now(),
  check (ends_at > starts_at)
);
create index bookings_user_id_idx on bookings (user_id);
create index bookings_doctor_starts_idx on bookings (doctor_id, starts_at);
```
- `timestamptz` always (stored in UTC). `text` with a CHECK instead of arbitrary `varchar(n)`. Money in integer cents or `numeric(12,2)`, never `float`/`real`.
- Identity columns over `serial`. UUIDs (`uuid default gen_random_uuid()`, built in since PostgreSQL 13) when ids are exposed publicly or generated by clients; UUIDv7 keeps index locality if available.
- PostgreSQL does **not** index foreign key columns automatically: add an index for every FK used in joins or deletes.
- `updated_at`: set it in the application or with a trigger.

## Constraints carry the business rules
- Prevent overlapping bookings per doctor with an exclusion constraint:
```sql
create extension if not exists btree_gist;
alter table bookings add constraint no_overlap
  exclude using gist (doctor_id with =, tstzrange(starts_at, ends_at) with &&) where (status <> 'cancelled');
```
- Partial unique index for "one active X": `create unique index one_active_cart on carts (user_id) where status = 'active';`
- Soft delete with `deleted_at timestamptz` plus partial indexes `where deleted_at is null`.
- Enumerations: CHECK constraints or a lookup table; native `enum` types are hard to change later.

## Indexes
- B-tree for equality and ranges; composite order: equality columns first, then the range or sort column (`(doctor_id, starts_at)` serves `where doctor_id = $1 and starts_at >= $2 order by starts_at`).
- `include` columns for index-only scans; GIN for `jsonb` containment and full-text (`to_tsvector`); `pg_trgm` GIN for `ILIKE '%term%'` search.
- Every index slows writes: add indexes for real queries, then verify with EXPLAIN.

## Reading plans
```sql
explain (analyze, buffers) select * from bookings where doctor_id = 7 and starts_at >= now() order by starts_at limit 20;
```
Look for `Seq Scan` on large tables, a big gap between estimated and actual rows (run `analyze`), sorts spilling to disk, and nested loops over many rows. Fix with an index, a rewritten query or fewer columns.

## Transactions and concurrency
- Default isolation is READ COMMITTED. Wrap multi-statement invariants in one transaction.
- Read-modify-write: `select ... for update` to lock the row, or optimistic locking with a `version` column (`update ... set version = version + 1 where id = $1 and version = $2`, zero rows updated means conflict, answer 409).
- Upsert: `insert into ... values (...) on conflict (user_id, day) do update set count = excluded.count;`
- Unique violations raise SQLSTATE `23505`, foreign key violations `23503`, check violations `23514`: map them to 409 or 422 in the API.
- Keep transactions short; never wait for user input or HTTP calls inside one.

## Pagination
Offset is fine for small tables and admin screens. For large, scrolling lists use keyset:
```sql
select id, starts_at from bookings
where user_id = $1 and (starts_at, id) < ($2, $3)
order by starts_at desc, id desc
limit 20;
```
with an index on `(user_id, starts_at desc, id desc)`.

## Migrations without downtime
- Add columns as nullable (or with a constant default, which is fast since PostgreSQL 11), backfill in batches, then add NOT NULL.
- `create index concurrently` for big tables (it cannot run inside a transaction: mark the migration non-transactional).
- Rename in steps (add new, write both, move reads, drop old). Never edit an applied migration.

## Operations
- Connection pooling: the app's pool (asyncpg, pg.Pool, SQLAlchemy pool) sized to a few connections per worker; PgBouncer for many processes.
- Least privilege: the app connects as a role without superuser or DDL rights in production.
- Backups: `pg_dump -Fc dbname > backup.dump`, restore with `pg_restore`. Document it in the README.
- Local development: `postgres:17-alpine` in docker compose with a volume and a `pg_isready` health check (see the docker playbook), or a native Windows install.
